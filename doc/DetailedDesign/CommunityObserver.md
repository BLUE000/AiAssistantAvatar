# CommunityObserver (コミュニティ見守り・対話促し) 詳細設計書

## 1. アーキテクチャ概要

`CommunityObserver` は、単語単位の静的フィルター（第1層モデレーション）をすり抜ける「普段の言動との乖離」「小さな不満・愚痴の蓄積」「メンタル低下の兆候」を客観的な過去ログから検知し、AI が話を聞き出すための対話ディレクティブを生成する独立 C++ コンソールアプリケーションである。

```
[Twitch / Discord チャット受信]
         │
         ▼
┌───────────────────────────────────────┐
│ 第1層: ScoreModerationEngine          │ ──(危険語検知)──> 【即時BLOCK (応答中断)】
└───────────────────────────────────────┘
         │ (SAFE通過: フィルター通過＝安全ではない)
         ▼
┌───────────────────────────────────────┐
│ AIClientManager (メインアプリ)        │
│   QProcess::start("CommunityObserver")│
└──────────────────┬────────────────────┘
                   │ コマンド引数 (--record --eval --user ... --text ...)
                   ▼
┌───────────────────────────────────────┐
│ CommunityObserver.exe (独立CLI)       │
│  1. ユーザー別過去ログ (JSON) 読込    │
│  2. 普段の傾向 (話題/トーン) と照合   │
│  3. 今回の発言をログへ追記保存        │
│  4. 違和感・継続性スコアリング        │
│  5. 判定結果・傾聴指示 JSON を stdout │
└──────────────────┬────────────────────┘
                   │ stdout JSON
                   ▼
┌───────────────────────────────────────┐
│ AIClientManager                       │
│   判定ディレクティブをプロンプトへ注入│
└──────────────────┬────────────────────┘
                   │
                   ▼
┌───────────────────────────────────────┐
│ Worker AI (Mistral / Groq 等)         │ ──> 「かなり強い言い方だけど、何かあった？」
└───────────────────────────────────────┘
```

## 2. CLI インターフェース仕様

### 2.1 実行コマンド書式
```bash
CommunityObserver.exe [OPTIONS]
```

### 2.2 主要オプション一覧
| オプション | 引数型 | 必須 | 説明 |
| :--- | :---: | :---: | :--- |
| `--eval` | なし | 任意 | 現在の発言に対して過去ログとの違和感・継続性判定を実行する。 |
| `--record` | なし | 任意 | 現在の発言をユーザーの過去ログファイルへ追記保存する。 |
| `--user` | 文字列 | 必須 | 対象ユーザー識別名（Twitch ID または Discord ユーザー名）。 |
| `--platform` | 文字列 | 任意 | プラットフォーム種別（`twitch`, `discord`, `direct`）。デフォルト: `twitch`。 |
| `--text` | 文字列 | 必須 | 評価・記録対象のユーザー発言本文。 |
| `--inspect` | なし | 任意 | 指定ユーザーの蓄積ログ統計・傾向サマリを表示する（デバッグ・管理用）。 |
| `--vacuum` | 整数 (日) | 任意 | 指定日数以前の古いログをクリーンアップ・ローテーションする。 |

## 3. 入出力 JSON スキーマ仕様

### 3.1 標準出力 (stdout) JSON スキーマ
CLI 実行完了時、標準出力へ以下の JSON を単一ブロックで出力して終了コード `0` で終了する：

```json
{
  "status": "DrasticChange",
  "user": "ponuponupuding",
  "platform": "twitch",
  "history_count": 28,
  "usual_topics": ["game", "casual_chat"],
  "usual_sentiment": "positive_friendly",
  "current_topic": "interpersonal",
  "current_sentiment": "negative_aggressive",
  "concern_level": 2,
  "anomaly_summary": "普段はゲーム話題中心の温和な発言が多いが、特定対象への強い否定・棘が出現",
  "directive": "[対話誘導指示: ユーザーから普段の傾向と大きく異なる強い感情・表現が発せられました。否定や説教をせず、『かなり強い言い方だけど、何かあった？』のように、ユーザーが自発的に事情を話せるよう優しく聞き返してください。]"
}
```

### 3.2 判定ステータス (`status`) 定義
| ステータス名 | 意味・発生条件 | 注入される `directive` |
| :--- | :--- | :--- |
| **`Normal`** | 普段の傾向と一致、または特段の違和感・過度な攻撃性がない通常状態。 | 空文字（通常通りのフレンドリーな会話応答） |
| **`DrasticChange`** | 普段は温和・冗談中心・ゲーム話題中心のユーザーから、突然特定対象への強い棘・否定・投げやりな発言が出た状態。 | 否定・説教をせず、「何かあった？」と話を開く方向へ促す傾聴指示。 |
| **`PersistentConcern`** | 同一の人物・話題に対する不満・敵意・愚痴が過去ログに複数回にわたり継続・蓄積している状態。 | 一方的に決めつけず、「前にも気にしてたみたいだけど、何かあった？」と状況説明を促す指示。 |

## 4. ログ蓄積・ファイル管理仕様

### 4.1 格納ディレクトリおよびファイル命名規約
- **格納パス**: `Config/observer_logs/<platform>_<user_id>.json`
- **文字コード**: UTF-8 (LF)
- **ファイル内構造**:
```json
{
  "user": "ponuponupuding",
  "platform": "twitch",
  "first_seen": "2026-07-01T12:00:00Z",
  "last_seen": "2026-08-15T21:30:00Z",
  "total_messages": 45,
  "records": [
    {
      "timestamp": "2026-08-15T21:30:00Z",
      "text": "みふぅさんにおすすめのオーバーウォッチのキャラクターとかいますか？",
      "topic": "game",
      "tone": "neutral"
    }
  ]
}
```

### 4.2 ローテーション・サイズ制限
- **保持最大件数**: 1 ユーザーあたり最大 100 件（超過時は古いレコードから FIFO で削除）。
- **最大保持期間**: 60 日間（`--vacuum` または記録時に 60 日以前の古いレコードを自動破棄）。
- **人物ラベリングの完全排除**:
  - 「危険人物」「クレーマー」といった主観的属性・評価ラベルは一切永続化せず、純粋な「発言日時・本文・客観的トピック・トーン分類」のみを保存する。

## 5. 違和感・傾向判定アルゴリズム

### 5.1 発言トピックおよびトーンの客観分類
各発言を以下の軽量ルールセットにより分類する：
- **トピック分類**:
  - `game`: ゲーム名、キャラ名、プレイ用語
  - `casual_chat`: 挨拶、天気、日常会話
  - `interpersonal`: 他ユーザーへの言及、人間関係、コミュニティ内の振る舞い
  - `complaint_venting`: 不満、愚痴、投げやり表現（「だるい」「無理」「疲れた」「消えろ」「嫌い」）
- **トーン分類**:
  - `positive`: 肯定・称賛・笑い（「草」「面白い」「好き」「ありがとう」）
  - `neutral`: 質問・情報共有・通常の会話
  - `negative_mild`: 軽い愚痴・不満
  - `negative_strong`: 強い棘・排除的表現・強い敵意

### 5.2 乖離度スコアリング
1. **ベースライン算出**: 過去レコード（直近 20 件以上）の `positive` / `neutral` / `game` 率を算出。
2. **ギャップ判定 (`DrasticChange`)**:
   - ベースラインが `positive` / `neutral` 80% 以上のユーザーから、突発的に `negative_strong` または特定個人への排除的発言が出た場合。
3. **蓄積判定 (`PersistentConcern`)**:
   - 直近 5 件中 3 件以上、または過去ログ内に同一対象への `negative_mild` / `negative_strong` が 3 回以上記録されている場合。

## 6. 本体アプリ (`AIClientManager`) 連携設計

### 6.1 `QProcess` による高速非同期/同期呼出
- `ScoreModerationEngine` による静的フィルター通過後、`AIClientManager::evaluateWithObserver` を実行。
- **タイムアウト保護**: 50ms 以内に CLI 応答がない場合はタイムアウトとして判定をスキップ（`Normal` 扱い）し、チャット応答の遅延を防止。
- **エラーハンドリング**: CLI の起動失敗・JSON パースエラー時は通常会話へ安全にフォールバック。

### 6.2 プロンプト生成への統合
`CommunityObserver` から `directive` が返却された場合、`formatRoleSeparatedPrompt` 内の `system` ロール末尾へディレクティブを動的挿入する。

```text
※現在の日時は 2026-08-15(土) 21:40:00 です。
...
[対話誘導指示: ユーザーから普段の傾向と大きく異なる強い表現が発せられました。否定や説教をせず、『かなり強い言い方だけど、何かあった？』のように、ユーザーが自発的に事情を話せるよう優しく聞き返してください。医療的判断や決めつけを行わず、友人として寄り添う姿勢を維持してください。]
```

## 7. 非機能・安全免責事項設計

1. **非医療・非専門的助言の制約**:
   - プロンプト指示に「医療的・心理学的診断や断定を行わないこと」を常に含める。
2. **スコープの明確化**:
   - ウェイクワードまたは接続中の特定チャンネルから受信されたテキストのみを対象とする。
3. **ローカル環境完結**:
   - 外部クラウドへのログ送信を行わず、すべて `Config/observer_logs/` のローカルファイルで完結する。
