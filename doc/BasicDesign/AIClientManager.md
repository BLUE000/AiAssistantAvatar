# 基本設計書 - AIClientManager ＆ ルーティングモジュール (AIClientManager.md)

## 1. 概要
`AIClientManager` は、全 AI プロバイダクライアント（さくらAI, Gemini, Groq, Mistral, HuggingFace, OpenRouter, Dummy）の生命周期管理、プロバイダ自動選定、およびレートリミット監視を担当するコアコンポーネントである。

---

## 2. 主要機能 ＆ コンポーネント設計

### 2.1 使用枠最大 AI 自動選定部 ＆ レートリミット追跡部 (`AIRouter` / `RateLimitTracker`)
- UI で全プロバイダのチェックが外されている場合、Release ビルドではダミーを稼働させず、`RateLimitTracker` から現在利用可能かつリミット残数（RPM/RPD）が最大の最適な AI クライアントを自動選定してルーティングする。
- **`RateLimitTracker` の3層ハイブリッド管理構造**:
  1. **ヘッダー同期層 (Primary Header Parsing)**: レスポンスヘッダーに含まれる制限値をダイレクトに優先適用。
  2. **ローカル内部消費計算層 (Local Consumption Estimator)**: ヘッダー未取得プロバイダに対し、Web設定での暫定上限値から、リクエスト毎の件数減算および文字列長に基づく概算トークン消費減算を行う。
  3. **適応学習層 (Adaptive Calibration Engine)**: 実際の利用中に発生するエラー（HTTP 429）や時間経過（リセット境界）から消費係数・安全マージン・復帰予測時間を自律学習し、使えば使うほど推算精度を向上させる。
  4. **ルーター側イベント駆動・UI表示トリガーオンデマンド評価機構**: タイマーを使わず、ルーター/マネージャーがプロバイダ選定・応答受信時、または UI からのステータス更新要求（「レートリミット」タブ表示時）を受け取った際に UTC 現在時刻（`currentDateTimeUtc()`）で期限切れ（`nextResetAt <= nowUtc`）を即座に判定。リセット済みのプロバイダの使用枠（`rpmRemaining = rpmMax`）および `available = true` フラグをその場で自動回復し、最新ステータスシグナルを発火する。




### 2.2 APIキー未設定 ＆ レートリミット全枯渇ガード部
- 有効な API キーが 1 つも設定されていない場合は外部リクエストを即座に遮断し、「*APIキー設定案内*」を表示する。
- 設定済みプロバイダが全てレートリミット到達時は、未設定キーの有無に応じた二分岐案内（リセットまでの残分秒 ＋ 未設定プロバイダの追加登録案内）を生成・表示する。

### 2.3 稼働中 AI プロバイダ・モデル情報提供部 (Active AI Status Context)
- 現在実際に選定・推論を行っている Worker AI (会話用) および Manager AI (評価用) のプロバイダ名および自動適用中モデル名をリアルタイム保持・提供する。
- ユーザーから「現在のAIモデルは？」「何のAIで動いている？」と質問された際に正確に自己回答できるよう、システムプロンプトのコンテキスト情報として自動注入する。

### 2.4 チャットコメント応答テキストの500文字自動分割 ＆ スローモード遅延キュー制御設計
- **500文字上限分割エンジン**:
  - AI 応答テキストが 500 文字（`QString::length()`）を超える場合、句読点（`。` `！` `？`）または改行コード（`\n`）を最優先の区切り位置としてサーチし、500文字以内の自然な文脈ブロックに自動分割する。
- **スローモード対応遅延送信キュー (Slow-Mode Delay Queue)**:
  - 分割された複数のコメント、および短時間の連続応答に対し、スローモード対応のインターバルタイマー（例: 1500ms）を介して順次 1 メッセージずつ送信し、プラットフォームの自動規制を回避する。

### 2.5 レートリミット問い合わせコマンド応答 ＆ システムナレッジプロンプト設計
- **`SystemResponseManager` での問い合わせ判定**:
  - ユーザーからのプロンプトに「レートリミット」「リミット」「制限」および「更新」「表示」「教えて」などのキーワードが含まれる場合、AI に投げる前に `SystemResponseManager` が自動応答する。
  - レートリミットステータスの要求（`emitCurrentStatus`）を連動発火し、画面の「レートリミット」タブを最新化させたうえで「*レートリミット情報を更新しました。『レートリミット』タブから各AIの利用枠や残量をご確認いただけます。*」と即答する。
- **システムプロンプトへの機能ナレッジ注入**:
  - AI に対し、「本システムには各AIのレートリミットや利用残量を表示・更新する『レートリミット』タブが備わっている」旨のナレッジをシステムプロンプトへ自動注入し、AI が「機能が実装されていない」と誤回答するのを防止する。

### 2.6 AI リクエスト送出遅延 (1秒未満の時差) 制御設計
- **Groq 制限回避 ＆ 送出インターバル制御**:
  - `AIClientManager` のリクエスト処理および `Manager AI` の自動評価処理において、リクエスト送信直前に 1 秒未満（約 600ms）の送出遅延（時差）を挟む。
  - 短時間での多重・連続 API 呼び出しを防ぎ、Groq や OpenRouter 等の外部 AI サーバー側で「不審な高頻度アクセス（Bot）」と誤判定されてセキュリティアラートが出されるのを防ぐ。

### 2.7 マネージャー使用 AI の Worker (クライアント) 優先度自動降格 ＆ Mistral RPM 適正化
- **マネージャー AI 使用プロバイダの末尾移動（優先度降格）**:
  - `buildFallbackProviderList()` にてフォールバック優先順序（`groq` → `mistral` → `huggingface` → `openrouter` → `sakura`）を構築する際、マネージャー AI で使用されているプロバイダ（`m_managerProvider`）をリストの最下位（末尾）へ自動で組み替える。
  - マネージャー評価と会話応答が同一プロバイダへ集中し、レート制限に達するリスクを回避する。
- **Mistral AI RPM デフォルト値適正化**:
  - Mistral AI の初期 RPM（`s.rpmMax`）を `1` から `30` へ変更し、連続発言時の不要なブロックを解消する。

### 2.8 話者・対話コンテキスト管理設計 (Speaker & Context Management)
- **6構造属性 (`SpeakerContext`) による発言メタデータのカプセル化**:
  - 発言者 (`speaker`)、宛先 (`target`)、発言種別 (`category`: AI自身/配信者/視聴者/システム) を `SpeakerContext` として保持する。
- **プロンプトヘッダータグ構造化 ＆ ガイドライン注入**:
  - AI への入力プロンプト頭部および対話履歴メッセージへ `[発言者: X (配信者/視聴者) | 宛先: Y | 種別: Z]` 形式でメタデータタグを自動付与する。
  - システムプロンプトへ「誰が誰に対して発言したかを明確に読み分け、他人の問題を話しかけた人の問題と誤解しない」コンテキストルールを自動注入する。

### 2.9 JSON 設定ファイルの 1 行コメント (`#`) フィルター設計
- **`JsonCommentRemover::stripHashComments`**:
  - `local_settings.json` の読み込み時、`QJsonDocument::fromJson` に引き渡す前に `#` コメント除去処理を噛ませる。
  - 行頭コメント（`# ...`）および項目末尾コメント（`"key": "val", # コメント`）をトリミング除去する。
  - 文字列クォーテーション内の `#`（例: `"api_key": "abc#123"`）はパース状態を管理して保護する。

### 2.10 レートリミット自動復帰 ＆ available フラグ即時復元設計
- **`RateLimitTracker::updateAvailable` の補正**:
  - `nextResetAt` が現在時刻を超過した際、`rpmMax <= 0` や `rpdMax <= 0`（-1: チェックバイパス）のプロバイダに対しても `rpmRemaining = -1`, `rpdRemaining = -1` に全量復帰させる。
  - リセット完了時に `nextResetAt` をクリアすると同時に、`available` フラグを `true` へ確定復帰させ、「残り0秒で到達中表示のまま固まる」現象を防止する。

### 2.11 残枠保持時の `available` 評価 ＆ タイマー自動起動設計
- **`RateLimitTracker::recordLocalConsumption` / `updateAvailable` の整合化**:
  - `recordLocalConsumption` で初回消費減算が発生した際、`nextResetAt` が未設定であれば 60 秒後のリセット時刻を自動設定する。
  - `updateAvailable` における `available` 判定条件を `rpmOk && rpdOk && tpmOk` の真偽値に正確に一致させ、残枠が存在する（`rpmRemaining > 0`）間は `available = true` を堅持する。

### 2.12 未初期化残量 (`-1`) 保持時の利用可能 (`Ok`) 判定設計
- **`RateLimitTracker::updateAvailable` の `rpmOk / rpdOk / tpmOk` 判定補正**:
  - 各残量変数が `-1` (未初期化/無制限) の場合、該当上限値 (`tpmMax` 等) が `> 0` であっても利用可能 (`Ok = true`) と判定する条件 `(remaining == -1)` を判定式に組み込む。

### 2.13 JSON 設定保存時の既存テキスト尊重 ＆ ピンポイント置換更新設計 (`JsonCommentRemover::updateExistingJsonText`)
- **`JsonCommentRemover::updateExistingJsonText` ユーティリティ設計**:
  - 設定保存時 (`AvatarWindow::saveSettings()` / `saveToFile()`)、既存の `local_settings.json` ファイルの元のテキスト（すべての `#` コメント行、空行、インデント構造）を読み込み保持する。
  - `QJsonObject` 内の各更新対象キーについて、既存テキスト内の `"key": value` 部分のみを正規表現/構文解析でピンポイント置換・書き換える。
  - 既存テキストに存在しない新規キーのみを適切な位置（または文末）に追加挿入する。
  - これにより、JSON 全体の自動シリアライズ上書きを回避し、既存テキスト内の全 `#` コメント行およびレイアウト・フォーマットを 100% 完全保護する。

### 2.14 応答完了時の状態変数全消去 ＆ 翻訳コマンド前置正規化設計
- **応答完了時・中断時の状態完全初期化 (`on_clientRequestFinished`)**:
  - 各 AI リクエストの処理完了時（正常応答、エラー発生、タイムアウト、翻訳処理時問わず）、宛先チャンネル変数（`m_currentTwitchChannel`, `m_currentDiscordChannelId`）および発言者変数（`m_currentRequester`）を `.clear()` して確実に完全初期化する。
  - 次のリクエストへ前回の返信先情報や話者識別子が残留・リークすることを防ぎ、人違いや他プラットフォーム（Twitch/Discord）への応答誤送信を全遮断する。
- **翻訳コマンド前置記号・ウェイクワード正規化判定**:
  - `!ai trans [言語] [テキスト]` や `/ai trans` などのウェイクワード付き入力に対し、判定処理の冒頭で前置記号（`!ai` 等）およびスペース・ゆらぎをトリミング正規化除去したうえで `startsWith("trans")` を評価する。
  - チャット・直接入力いずれから入力された場合でも 100% 確実に翻訳モード（`m_isTranslationRequest = true`）として認識・処理する。

### 2.15 ユーザー名プロンプトインジェクション ＆ マルチユーザー自然言語省略応答設計
- **優先呼び名・愛称設定時のプロンプトインジェクション**:
  - `user_names.json` に優先呼び名 (`preferred`) または愛称リスト (`nicknames`) が明示的に登録されている場合のみ、システムプロンプトへ「〇〇さん、」等の呼び名指示をインジェクトする。
- **未登録・デフォルトIDユーザーに対する自然言語省略応答指示**:
  - 優先呼び名が未設定（未登録）のアカウントに対しては、回答冒頭での強制的な名前呼びかけ（「アカウント名さん、」等）の指示を廃止する。
  - プロンプト指示として「回答冒頭での強制的な名前の呼びかけは行わず、日本語として自然な文章（例:『それは〇〇だよ！』『〇〇です』等）で直接回答してください」とインジェクトし、自然な主語/対象の省略応答を指示・許可する。
- **マルチユーザー環境における他話者誤認防止**:
  - システムプロンプトへ「本チャットは不特定多数の視聴者が参加するマルチユーザー環境である」旨を明記し、会話履歴やセッション要約に過去の他ユーザー名（例: ミフさん）が含まれていても、過去の会話相手と混同せず、現在の発言者に対して適切かつ独立して回答するよう制約を付与する。

### 2.16 Web検索・外部知識応答における情報量制御設計 (F-34: 3段階回答モード)
- **調査量と回答出力の二層分離アーキテクチャ**:
  - Web 検索（`SearchManager` による Tavily / DDG 検索）やナレッジ検索等のデータ収集フェーズでは十分な情報を網羅的に取得し、内部保持する。
  - 回答生成フェーズにおいて、ユーザーの入力意図から回答モード（`ResponseDetailMode`: `SHORT`, `NORMAL`, `DETAILED`）を判定し、システムプロンプトへ対応する出力長・粒度制約を注入することで、最終出力テキストの長さのみを独立して制御する。
- **3段階回答モード制御**:
  - `SHORT` (デフォルト): 配信中に短時間で読める 1〜3 文程度。結論と主要因を優先し、専門用語・細かい数値を抑制。
  - `NORMAL`: 数段落程度。「なぜそうなるのか」の理由、平易な解説付き専門用語、重要数値を含めて説明。
  - `DETAILED`: 長文詳細解説。詳細な背景、専門用語、条件、例外事項を含めて網羅的に解説。
- **意図判定 ＆ 段階的詳細化・粒度縮小**:
  - ユーザー入力内のキーワード（「詳しく」「詳細に」「もっと教えて」等）から詳細化モードを自動判定。
  - 「細かすぎる」「長すぎる」「詳しすぎる」「要点だけ」等の指摘表現を検知した場合、即座に `SHORT` モードへ縮小し、直前の回答内容を 1〜2 文程度に圧縮・再要約して平易に言い直すようプロンプト制御する。
### 2.17 Twitch クリエイター紹介文生成コンソールアプリ (`TwitchIntroGenerator`) 連携設計
- **紹介文生成およびレイド時シャウトアウト処理の独立プロセス化 (Separation of Concerns)**:
  - Twitch レイド受信時、およびチャットでの会話トリガー（「〇〇さんを紹介して」「!so 〇〇」）におけるクリエイター紹介文生成ロジック（Helix API からの情報収集 ＋ プロンプト構築 ＋ AI生成）を、独立したコンソールアプリ（`TwitchIntroGenerator.exe`）に委譲する。
- **メインアプリとコンソールアプリの明確な役割分担**:
  - **コンソールアプリ (`TwitchIntroGenerator.exe`)**:
    - 指定された Twitch ユーザーのクリエイター情報（Bio, 配信タイトル, 直近の配信ゲーム履歴, SNSリンク）を Helix API から取得。
    - **レイド時 (`--mode raid`)**: レイド歓迎プロンプトによる紹介文生成と同時に、Twitch 公式 `/shoutout` REST API を自動送信。
    - **会話紹介時 (`--mode conversation`)**: `/shoutout` REST API は送信せず、純粋な紹介文生成のみを実行。
    - 生成された紹介文テキストを標準出力（stdout）に出力する。
  - **メインアプリ (`AIClientManager`)**:
    - レイド検知およびチャットコマンド検知時に `QProcess` を介して `TwitchIntroGenerator` を適切なモード引数（`--mode raid` / `--mode conversation`）で非同期実行。
    - 生成された紹介文テキストを受け取り、Twitch チャットへの投稿（PRIVMSG / `/announce`）およびアバター発話イベントを送出する。
    - レイド時における 120 秒クールタイム監視および待機キュー管理をメインアプリ側で一元統括する。
  - **障害時フォールバック**:
    - CLI の実行エラーまたはタイムアウト（15秒）時は、メインアプリ側で安全にフォールバックメッセージ（通常のお礼・紹介コメント）を出力する。

### 2.18 Google Gemini プロバイダ ＆ Gemini コンソールアプリ (`GeminiChatter`) 連携設計
- **プロバイダ統合アーキテクチャ**:
  - Google AI Studio の無料枠 API（`gemini-2.0-flash`, `gemini-1.5-flash`、15 RPM / 1,500 RPD）を直接利用可能なクライアントエンジン（`GeminiAIClient`）として統合。
  - プロバイダ自動ローテーションおよびフォールバック機構（Groq $\rightarrow$ Gemini $\rightarrow$ さくらAI $\rightarrow$ Mistral $\rightarrow$ OpenRouter $\rightarrow$ HuggingFace）に組み込み、無料枠の多さと高速性を最大限に活用。
- **Gemini コンソールアプリ (`GeminiChatter.exe`)**:
  - 独立プロセスとして Gemini 推論を実行する CLI ツールを提供。
  - メインアプリおよび外部ツールから `tools/GeminiChatter.exe` を非同期起動可能。
  - プロセス起動時は `ProcessUtils` により `PATH` 前置注入と DLL 共有を行い、軽量かつ安全に実行。
