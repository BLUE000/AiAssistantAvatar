# 基本設計書 - UI ＆ 表示モジュール (UI.md)

## 1. 概要
本モジュールは、メインアバターウィンドウ (`AvatarWindow`)、会話履歴ビューア (`HistoryViewerDialog`)、およびレートリミット管理専用タブ (`RateLimitTabWidget`) の設計を定義する。

---

## 2. 主要機能 ＆ コンポーネント設計

### 2.1 レートリミット管理専用タブ (`RateLimitTabWidget` - F-16-10)
- 設定画面に「レートリミット」専用タブを新設し、ユーザーがクリック操作を行わなくても全プロバイダの最新ステータスと使用量プログレスを操作不要（開くだけ）で表示する。
- C++ 側に特定プロバイダ用固定フィールドを持たず、I/F 等から提供される `RateLimitQuotaItem` を動的に生成描画し、非対応項目の `N/A` や `-` の曖昧表示を完全全廃する。

### 2.2 会話履歴ビューア (`HistoryViewerDialog` - F-30)
- 左右 2 ペイン構成で過去の対話ログと吹き出し表示をブラウジング可能にする。

### 2.3 AI設定タブ レイアウト (Worker AI 設定 UI インライン統合 ＆ アラインメント整備)
- Worker AI 設定グループ内の各プロバイダ項目（Mistral AI, Cerebras AI, Groq, HuggingFace, OpenRouter, さくらAI）において、有効化チェックボックスの文言を「有効」へ統一する。
- **1行目 (APIキー行)**: `[プロバイダ名:]` ラベルの右側に、`[レ] 有効` チェックボックスと API キー入力欄 (パスワード伏字・残スペース全幅活用) をインライン配置する。
- **2行目 (モデル選択行)**: `[モデル:]` ラベルの右側にモデル選択コンボボックスを配置し、1行目の `[レ] 有効` チェックボックスの左端位置と 2行目のコンボボックスの左端位置が綺麗に揃うようアラインメント（左端位置合わせ）を統一する。
- **Tavily 検索キー項目**: 検索用 API キー入力項目 `Tavily キー (任意):` は、変更なしでグループ最下段に単独行として維持配置する。

### 2.4 データ駆動型 AI プロバイダ UI 自動生成 ＆ モデル全自動選択モジュール
- 将来的な AI プロバイダ追加時のコード重複および肥大化を根絶するため、プロバイダ属性を定義する構造体リスト (`QList<ProviderConfigSpec>`) を導入する。
- プロバイダの追加・更新・削除は構造体リストの定義変更のみで行い、UI生成、アラインメントレイアウト構築、チェックボックス排他制御、およびJSON設定のロード・保存処理をすべて単一ループで全自動処理する。
- **モデル全自動選択機能 (Auto Model Selection)**:
  - モデル選択コンボボックスの先頭選択肢を「`自動選択 (推奨)`」に統一する。
  - ユーザーがモデルを未指定（「自動選択」のまままたは空文字）にした場合、各 AI クライアント内部で最新・推奨の推論モデル（または取得可能な最適モデル）を全自動選択してリクエストを実行する。

### 2.5 アバター共通・基本設定 ＆ OBS設定のUI非表示化仕様
- **「アバター共通・基本設定」UIのシンプル化**:
  - グループボックス内にはアバター名 (`m_avatarNameEdit`) およびアバタースキン選択 (`m_comboAvatarSkin`, `m_btnSkinBuilder`) のみを集約配置する。
  - 「名前（アバター名）呼ばれて反応する」 (`name_reaction_enabled`) チェックボックス、およびウェイクワード・判定フォームを画面 (UI) から削除し、設定ファイル (`local_settings.json`) 管理とする。
- **「OBS / 描画設定」ポート項目のUI非表示化**:
  - 「WebSocketポート(OBS用)」 (`ws_port`) および「HTTP配信ポート」 (`obs_http_port`) の入力フォームを画面 (UI) から削除し、設定ファイル (`local_settings.json`) 管理とする。

### 2.7 音声入力 (STT) 共有マイクアクセス ＆ 会話状態遷移設計 (F-2)
- **マイク共有非独占（Shared Mode）仕様**:
  - Windows SAPI の `SpSharedRecognizer` および WASAPI Shared Mode を使用し、OBS や Discord とマイクデバイスを共用する。
- **「音声」ボタンの PTT (長押し/トグル) 制御**:
  - ボタン押下時 (`pressed`) ➔ UI表示を `🎤 録音中...` (赤色スタイル) に切り替え、`STTManager::on_startListening()` を呼び出す。
  - ボタン解放時 (`released`) ➔ UI表示を `音声` (通常スタイル) に戻し、`STTManager::on_stopListening()` を呼び出す。
  - **PTT入力の無条件送信**: PTT操作による音声入力は意図的なボタン押下であるため、アバター名の有無にかかわらず即座に AI 問いかけ処理へ転送する。
- **会話状態遷移回路 (Idle ➔ Active ➔ Silence Timeout ➔ Idle)**:
  - **待機状態 (Idle)**: マイク常時監視時、発言テキスト内にアバター名（例: ぶるたろう）またはウェイクワードが含まれない場合は自動的に無視・破棄する。
  - **日本語表記ゆれ自動吸収・正規化照合**: Speech-to-Text エンジン（Google WebSTT, SAPI, Whisper等）により「ぶるたろう」が漢字・カタカナ・濁音/半濁音（例: `プル太郎`, `ブル太郎`, `ブルタロウ`）として変換認識された場合でも、判定処理において「ひらがな・カタカナ相互変換」および代表的漢字表記のゆらぎを自動的に吸収・正規化し、一致とみなして正しくウェイクワード検出する。
  - アバター名を検出した場合、アバター名を除去して AI 問い合わせを発行し、会話アクティブ状態（Active）へ遷移する。
  - **会話アクティブ状態 (Active)**: アバター名を省略した連続会話を許可する。発言があるたびに無音タイマーをリセットする。
  - **無音タイムアウト復帰**: 設定値 `voice_silence_timeout_ms` (初期値: 1000ms) の間無音が継続した場合、タイマー満了により自動的に待機状態 (Idle) へ復帰する。
- **認識結果の AI 自動ルーティング**:
  - 音声認識完了イベント (`VoiceInputCompleted`) 受信時、`CoreModule` は状態遷移に基づいて自動的に `requestAIExecution` シグナルを発火し、認識テキストを AI 返答・吹き出し表示・OBS通知処理へ直結させる。
- **サブPC（別マシン）動作 ＆ ネットワーク STT 注入**:
  - サブPC単体での動作を保証し、HTTP/WebSocket 経由の外部 STT テキスト注入処理に対応する。

### 2.8 ブラウザ用 WebSTT 音声入力 ＆ ウェイクワード常時監視 Web 画面設計
- **HTML/JS インターフェース提供**:
  - ブラウザで `http://<IP>:58082/stt` へアクセスした際、WebSpeech API を使用したリアルタイムマイク音声認識 ＆ ウェイクワード常時監視 Web ページ (HTML) をレスポンス返却する。
- **ハンズフリー音声呼びかけ動作**:
  - Web ページ上でブラウザマイクを常時監視し、ユーザーが「ぶるたろう」等のアバター名やウェイクワードを喋ったことを検知すると、続く発話テキストを本アプリの `/stt_input?text=...` へ自動送信し、コア側の状態遷移回路と連動して AI アバターと会話を開始する。

### 2.9 レートリミットタブ 3 段階直感モニタリング ＆ ガード設計
- **3 段階ステータス表示形式 (「これはいっぱい使える」「もうすぐ上限」「今使えない」)**:
  - 🟢 **利用可能**（緑色バー）: 残り枠 30% 以上保持時。メッセージ「これはいっぱい使えるよ！」の状態を示す。
  - 🟡 **もうすぐ上限 (残りX回)**（オレンジ色バー）: 残り枠 30% 未満。メッセージ「もうすぐ使えなくなるよ！」の状態を示す。
  - 🔴 **今使えないよ (解除まで あとXX秒)**（赤色バー）: 残り枠 0 回、または HTTP 429 エラー時。メッセージ「今使えないよ！」の状態を示す。
- **誤値自動クレンジング ＆ 最低安全上限値保持**:
  - `Mistral` の上限値が `1` などの不当な数値で保存されている場合、起動時に標準枠（Mistral: 30 RPM, Groq/Cerebras: 30 RPM, HuggingFace/OpenRouter/Sakura: 60 RPM）へ強制補正する。
