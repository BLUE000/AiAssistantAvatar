# 意思決定ログ - Twitch認証フローの変更とWebHook外部連携およびリファクタリング

## 日時
2026-06-22 00:59:00 (JST)

## 1. 意思決定の背景と目的

### A. Twitch認証の自動リフレッシュ（Authorization Code Flow）への移行
- **背景**: 既存の `Implicit Flow` ではアクセストークンの有効期限（約60日）が切れるたびにユーザーがブラウザでの再認可操作を強いられる問題があった。
- **決定**: トークン更新エンドポイントを用いてサイレント自動更新ができる `Authorization Code Flow` に移行する。
  - `twitch_client_secret` および `twitch_refresh_token` を設定・保存対象に追加。
  - IRC接続失敗（認証エラー）検知時に、保存されているリフレッシュトークンを使ってバックグラウンドで新しいアクセストークンを自動取得・更新する。
  - アカウント切り替えを容易にするため、ブラウザ認可画面のURLに `force_verify=true` パラメータを付与する。

### B. WebHookによる非同期状態通知機能の追加
- **背景**: アバターの状態やAIの応答（セリフ）をOBS等の外部配信支援ソフトウェアや連携用オーバーレイと連動させやすくするため、WebSocket配信に加え、汎用的なWebHook（HTTP POST）での状態送信が必要となった。
- **決定**:
  - 設定タブに `webhook_url` と `webhook_enabled` を新設し、UIから有効/無効および通知先を制御可能にする。
  - アバターの状態変化時（`avatar_changed` イベント）およびAI回答受信時（`ai_response` イベント）に、非同期（UIスレッドをブロックしない `QNetworkAccessManager` 経由）でPOST送信する。

### C. 空のウェイクワード（ウェイクワード無効）の許容
- **背景**: 設定画面でウェイクワードを空にして保存しても、アプリ起動・設定ロードのタイミングで `"アバターさん"` に強制上書き（フォールバック）されてしまうバグがあり、ウェイクワード機能を完全にオフ（または全コメント無反応など）にすることができなかった。
- **決定**: ロード処理で設定ファイルにキーが存在しているか (`obj.contains("twitch_wakeword")`) を明示的にチェックし、空文字であってもそれを設定値として尊重するようにロードロジックを修正。

### D. デフォルト定数定義の一本化（リファクタリング）
- **背景**: デフォルトのポート番号（`58081`, `48080`）、ウェイクワード（`"アバターさん"`）、AIプロバイダ名（`"dummy"`）などのフォールバック初期値が、複数のソースコード（`avatar_window.cpp`, `twitch_reader.cpp`, `ai_client_manager.cpp`）で個別にハードコーディングされており、将来の変更に弱い設計となっていた。
- **決定**: 全モジュールが参照する共通ヘッダー `src/app_event.h` に `ConfigDefaults` 名前空間を新設し、定数を `inline const` で一本化して管理する。

## 2. 影響範囲と対策
- **互換性**: 設定ファイル `local_settings.json` に新しい設定キーが追加されるが、読み書き時にデフォルト値への安全なフォールバックを施しているため、古い設定ファイルが存在していてもエラー無く起動する。
- **単体テスト**: テストコード `test_twitch_reader.cpp` における `setSettings` メソッドの呼び出し引数（シークレットキーの追加）を追記し、単体テストプログラムのビルド・実行互換性を維持。

### E. Web検索（DuckDuckGoスクレイピング）HTMLパース処理の修正
- **背景**: Tavily APIキーが未設定（空）の際、自動でDuckDuckGo検索へフォールバックするが、パース正規表現のバグにより検索結果が抽出されず、AIが「外部検索が制限されています」と誤回答していた。
- **決定**:
  1. **ロボット検知の判定修正**: ロボット検知判定で `html.contains("robot")` としていたため、正常なHTMLに含まれる `<meta name="robots" ...>` タグに部分一致してしまい、常に「Blocked or Rate Limited」と誤判定されてしまうバグを修正。判定を `robot check` に変更。
  2. **ブロック抽出の早期打ち切り回避**: `bodyRegex` の先読みアサーションに `|<!--` が含まれていたため、検索結果ブロック直後にある `<!-- This is the visible part -->` というコメント部分でマッチが即座に打ち切られていた問題を修正（`web-result` クラスを持つ `div` を基準にするよう変更し、`|<!--` 終了条件を削除）。
  3. **属性順序変化への対応**: `titleRegex` において、`rel="nofollow"` などが `class` の前に来るようなHTML属性の順序変化に耐えるよう、aタグ全体を抽出したあとで別途 `href` 属性の値を抜き出すようパース設計を変更。

### F. OBS / WebHook への状態変更通知（notifyAvatarChanged）の接続
- **背景**: アバターの状態やバリアント画像が変わっても、WebSocket接続中のOBSや外部WebHookへの状態変化イベントが一切通知されていなかった。
- **原因**: 状態通知を行う `notifyAvatarChanged()` 関数が定義されているだけで、実際の状態変更箇所から呼び出されていなかった。
- **決定**: アバター画像や状態が切り替わる根本的な関数（`updateAvatarDisplay`, `switchToNextVariant`, `stepAnimationFrame`）の最後に `notifyAvatarChanged()` の呼び出しを追加し、リアルタイムでの状態変更ブロードキャストを有効化した。

### G. Twitch OAuth認可開始時のクライアントシークレット必須バリデーションおよびエラー詳細の表示
- **背景**: Twitch認可コードフローにおいて、`Client Secret` が設定されていない状態で「Twitch認証開始」を起動すると、ブラウザから認証コードを受け取った後の最終トークン取得リクエストで必ず `HTTP 400 Bad Request` になり、ユーザーからは原因不明のエラーに見える問題が発生した。
- **決定**:
  1. **認可開始時の事前バリデーション**: `on_twitchReauthRequested` メソッドに `m_clientSecret` の空チェックを追加し、シークレットが設定されていない場合はブラウザを開く前に「クライアントシークレットが設定されていないため認証を開始できません」とUIへ通知して早期リターンするよう修正。
  2. **詳細エラー内容のUI表示**: トークン取得APIがエラー（HTTP 400 等）を返した際、レスポンスのJSONからエラーメッセージ（例: `client_secret is missing` 等）を取り出し、UIダイアログのエラー詳細として `Error transferring... (エラーメッセージの内容)` の形式で追記表示するよう修正。
