# DecisionLog — 2026-08-05 03:33:15

## 決定事項：Twitch OAuth認証ボタン押下時の非GUIスレッドからの QDesktopServices::openUrl 呼び出し修正 (スレッド安全化)

### 背景
会話履歴表示ボタン等は動作するようになったが、Twitch OAuth認証ボタンを押すとアプリがフリーズし異常終了する現象が継続していた。

### 根本原因の特定
ログとソースコードの解読結果：
`TwitchReader::on_twitchReauthRequested()` から呼び出される `TwitchReader::startOAuthServer()` 内で、ブラウザを開くために `QDesktopServices::openUrl(QUrl(authUrl))` が呼び出されていた。
しかし、`TwitchReader` オブジェクトはメイン GUI スレッドではなく常駐ワーカースレッド `twitchThread` 上で動作している。

Qt および Windows OS (ShellExecute/COM API) の仕様上、`QDesktopServices::openUrl` はメイン GUI スレッドのイベントループから呼び出されなければならない。
ワーカースレッドから呼び出された場合、アパートメント違反、UIコンテキストの非整合、あるいはミューテックスのデッドロックが発生し、即座にアプリケーションがフリーズ・異常終了する。

また、`AIClientManager::openKnowledgeInputFolder()` においても、`aiThread` (ワーカースレッド) 上から `QDesktopServices::openUrl` を直接呼んでいる箇所が存在した。

### 修正方針
1. `src/twitch/twitch_reader.cpp`:
   `QDesktopServices::openUrl(QUrl(authUrl))` を `QMetaObject::invokeMethod(qApp, ... Qt::QueuedConnection)` を用いてメイン GUI スレッドのイベントループへ安全にディスパッチするように変更。
2. `src/ai/ai_client_manager.cpp`:
   `AIClientManager::openKnowledgeInputFolder()` 内の `QDesktopServices::openUrl` も同様に `QMetaObject::invokeMethod(qApp, ... Qt::QueuedConnection)` へ修正。

### 変更ファイル
- `src/twitch/twitch_reader.cpp`
- `src/ai/ai_client_manager.cpp`

### 期待される効果
Twitch OAuth 認証ボタンを押した際、メイン GUI スレッド安全にブラウザが開くようになり、非GUIスレッドからのUI/OSシェルアクセスに伴うフリーズ・異常終了が完全に解消される。
