# Decision Log (意思決定ログ)

## 日時
2026-07-22 20:11:00

## 件名
F-29: マークダウン汎用データストレージ ＆ インデックス抽出機能 (Markdown Data Storage Engine) の設計と実装

---

## 背景・コンテキスト
- 配信主（ユーザー）がゲームの必要素材データ、占い、ガチャ景品などの構造化データを手軽に参照させたい。
- SQLやDBの専門知識がない配信主でも、テキストエディタでマークダウンテーブル（`.md`）を書くだけでデータベース化・情報源として扱える仕組みが求められた。
- 一方で、任意ディレクトリへのアクセスを許可すると、ディレクトリトラバーサル攻撃（`../` による外部ファイル漏洩）や個人情報アクセスのセキュリティリスクが発生する。

---

## 意思決定事項

1. **データストレージの完全単一責務化 (`MarkdownTableEngine`)**:
   - `knowledge/` ディレクトリ配下を純粋なデータ保管場所（データストレージ）として位置づける。
   - プログラム側には「占い専用」「ガチャ専用」などのドメイン固有ロジックを持たせず、純粋なテーブルパース・検索・ランダム抽出 API に特化。
   - 機能の構築（例: 占いやガチャ）は、ナレッジ指示文章（プロンプト）側が「どのテーブルのどのデータを取り出してどう扱うか」を定義するアーキテクチャ（データとロジックの完全分離）を採用。

2. **任意グループ分けディレクトリ階層メタデータ構造**:
   - サブフォルダ名を特定機能名に固定せず、`knowledge/[情報グループ]/[カテゴリ]/[テーブル].md` の任意階層構造を尊重してメタデータマップ化。

3. **クロステーブル（異領域）ランダム抽出マクロ**:
   - `TableSearch(group, category, table, searchKey, targetColumn)`
   - `TableSelectRandom(group, category, table, targetColumn)`
   - 異領域テーブル（例: 占いデータとゲームアイテムデータ）を跨いだランダム抽出・ナレッジ合成を可能にするマクロ評価器を提供。

4. **厳格なサンドボックス境界**:
   - ルートパスを `knowledge/` 専用に固定。
   - `QDir::cleanPath` および `canonicalFilePath` により `knowledge/` ルート外へのアクセスをプログラムレベルで物理遮断。対象を `.md` / `.txt` に限定。

---

## 実施結果と影響
- SQL等の専門技術なしに、配信主が手軽にゲーム図鑑やオリジナルガチャ情報源を作成・拡張可能となった。
- ディレクトリトラバーサルリスクが解消され、安全にナレッジデータベースの運用が可能となった。
- `test_search_manager.cpp` 内の `MarkdownTableEngineTest` (UT-TABLEDB-01 ~ UT-TABLEDB-06) を含む全 50 件の CTest 単体テストが 100% PASS。
- リモート `origin/master` へプッシュ完了。
