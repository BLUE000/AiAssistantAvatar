# DecisionLog: 2026-08-10_23-55-25

## 対象フェーズ
実装フェーズ・単体試験フェーズ

## 変更理由 (Why)

### 問題
OBS ブラウザソースでアバターのアニメーションが表示されなくなった。
ログでは AvatarChanged イベントは正常に発生しているが、OBS 側に届いていなかった。

### 根本原因
saveSettingsFromUI() 関数内で、websocket_port キーが設定ファイルに存在しない場合のデフォルト値として
ConfigDefaults::TWITCH_PORT (48080) を誤って使用していた（コピペミス）。

本来は ConfigDefaults::WEBSOCKET_PORT (58081) であるべき。

これにより設定保存時に websocket_port = 48080 が書き込まれ、以降 OBS WebSocket サーバーが
ポート 48080 で起動するようになった一方、avatar_obs.html は 58081 に接続しようとするため、
WebSocket 接続不成立 → broadcastToOBS() が誰にも届かない状態になっていた。

## 変更内容

### src/ui/avatar_window.cpp (L1651-1654)

修正前:
  if (!obj.contains(websocket_port)) {
      obj[websocket_port] = ConfigDefaults::TWITCH_PORT;  // 誤: 48080
  }
  if (!obj.contains(ws_port)) {
      obj[ws_port] = 58081;
  }

修正後:
  // websocket_port: 旧フォーマットにキーがない場合のみ追記（既存値は保持・上書きしない）
  if (!obj.contains(websocket_port)) {
      obj[websocket_port] = ConfigDefaults::WEBSOCKET_PORT; // 正: 58081
  }

- ws_port キーは websocket_port と重複するため廃止
- 設定ファイルに既にキーが存在する場合は一切変更しない（既存ユーザー設定を保護）

### test/test_ai_client.cpp (末尾に追加)

WebSocketPortDefaultTest クラスとして 4 ケースのユニットテストを追加:
1. MissingKeyIsFilledWithDefaultPort: キーなし -> 58081 が補完される
2. ExistingPortValueIsPreserved: 既存値 12345 -> 上書きされない
3. DefaultPort58081IsPreserved: 正常値 58081 -> 変わらない
4. TwitchPortIsNotUsedAsDefault: 48080 がデフォルトに使われない（回帰テスト）
