# 意思決定ログ - Twitch認証フローの手動ログイン方式（Implicit Flow）への差し戻し

## 日時
2026-06-22 09:33:00 (JST)

## 1. 意思決定の背景と目的

### A. Twitch認証フローの Implicit Flow（手動ログイン方式）への差し戻し
- **背景**: 
  - 前回の設計変更により、トークンの自動リフレッシュができる `Authorization Code Flow` に移行したが、Twitch開発者コンソールでアプリケーション登録時に「公開（Public）」を選択した場合、Client Secretは発行されず、後から「機密（Confidential）」へ種別変更もできない。
  - デスクトップアプリを一般ユーザー向けに配布するユースケースでは、共通のクライアントシークレットをアプリバイナリに埋め込むことは重大なセキュリティ漏洩リスクとなる。また、一般ユーザー各自に個別の「機密アプリ」を作成・設定させるのも導入ハードルが非常に高い。
  - サーバ仲介なしで安全にトークンを取得するデスクトップアプリの性質に適合させるため、シークレットを使用しない `Implicit Flow` に戻すことが最も現実的かつ安全な選択肢と判断した。
- **決定**:
  - 認証フローをクライアントシークレット不要の `Implicit Flow` へ差し戻す。
  - 設定ファイル `local_settings.json` および設定UI（設定タブ）から `twitch_client_secret` （クライアントシークレット）および `twitch_refresh_token` （リフレッシュトークン）の項目を削除。
  - トークンの自動サイレントリフレッシュ機能を廃止し、トークン切れや認証エラー検知時にはユーザーに手動での再認可（「Twitch認証開始」ボタンのクリック）を促す。
  - ローカル一時HTTPサーバーによるトークン受け取りにおいて、ブラウザへのリダイレクト時に付与されるURLフラグメント（`#access_token=...`）を、JavaScriptを返答することでパースさせ、再度 `/token?access_token=...` へ再送信させて抽出するロジックを復元・適用する。

---

## 2. 影響範囲と対策

- **設定ファイル**: `local_settings.json` のロード・セーブ時に `twitch_client_secret` および `twitch_refresh_token` の処理を行わないようにする。
- **UI**: 設定タブUIからクライアントシークレットの入力欄（`m_twitchClientSecretEdit`）を削除。
- **テストコード**: 単体テスト `test_twitch_reader.cpp` において、`TwitchReader::setSettings()` の引数から `clientSecret` が削除されるため、呼び出し箇所のパラメータ数を調整する。
- **WebSocketポート自動追従**: 設定タブからWebSocketポート（`websocket_port`）が変更された際、表示用アセットの `pic/avatar_obs.html` にハードコードされている接続先ポートが自動更新されない問題があった。そのため、設定保存時にHTMLファイルを自動走査し、ポート記述を置換して同期するロジックを `saveSettingsFromUI()` に追加する。

## 3. 実装結果と検証

### A. ソースコード修正内容
1. **UIおよび設定処理 (`src/ui/avatar_window.h`, `src/ui/avatar_window.cpp`)**:
   - `m_twitchClientSecretEdit` ウィジェット、およびメンバ変数 `m_twitchClientSecret`, `m_twitchRefreshToken` を削除。
   - `local_settings.json` のロード処理 (`loadSettings()`) およびセーブ処理 (`saveSettingsFromUI()`) からクライアントシークレットとリフレッシュトークンのキーを削除。
2. **Twitchモジュール (`src/twitch/twitch_reader.h`, `src/twitch/twitch_reader.cpp`)**:
   - `setSettings` などの引数から `clientSecret` を除外。
   - 認可開始時にブラウザで開くURLのパラメータを `response_type=token` に変更。
   - 一時HTTPサーバー (`handleNewConnection`) のリダイレクト受信処理を更新。ブラウザからの一回目アクセス時に、ハッシュをパースして `/token` に転送する JavaScript を含む HTML を返答し、二回目の `/token?access_token=...` アクセス時にアクセストークンを安全に抽出する方式を復元。
   - 不要になった自動リフレッシュ処理 (`refreshTwitchToken` / `requestTokensWithCode` / `onTokenRequestFinished` 等) を削除。
3. **WebHook起動時クラッシュ対策 (`src/ui/avatar_window.cpp`)**:
   - `webhook_enabled` が有効の際に、コンストラクタ初期段階で呼び出される `updateAvatarDisplay("idle")` 内の `notifyAvatarChanged()` で `m_webhookNetworkManager` が `nullptr` 参照を引き起こすバグを解決。
   - `m_webhookNetworkManager` の初期化とシグナル接続処理を、コンストラクタ冒頭の最優先領域（サイズ設定直前）へ移動。
   - コンストラクタ末尾（188行目付近）に残存していた重複する初期化コードを削除。
4. **WebSocketポート自動更新ロジックの追加 (`src/ui/avatar_window.cpp`)**:
   - `saveSettingsFromUI()` の中で `pic/avatar_obs.html` のパスを動的に検出。
   - `QRegularExpression` を用いて、HTMLファイル内の `ws://localhost:\d+` を、入力された新しいポート番号に置換して上書き保存する処理を追加。
   - 置換を行うために `avatar_window.cpp` に `#include <QRegularExpression>` を追加。
5. **テストコード (`test/test_twitch_reader.cpp`)**:
   - `setSettings` の呼び出し引数を修正。
6. **要求キューと可変吹き出し表示時間の仕様追加 (`src/ui/avatar_window.cpp`, `src/core_module.cpp`, `src/main.cpp`, `pic/avatar_obs.html`)**:
   - Twitchチャットコメント受信時や音声入力完了時に、直接AIリクエストを発火させず、UI側の要求キュー `m_aiRequestQueue` に一度格納して直列に順次処理する方式へ変更。
   - `CoreModule` 側の直列中継ロジックから直接のAI要求発火を削除し、UIのキュー制御タイミングで `requestAIExecution` シグナルを通じてAI要求を実行するように変更。
   - 設定タブに「次の要求がある時の表示秒数 (秒)」「次の要求が無い時の表示秒数 (秒)」を追加し、`local_settings.json` のロード・セーブを紐付け。
   - AI応答受信時、キューに次の要求が残っている場合は「溜まっている時の表示秒数」（デフォルト5秒）、無い場合は「無い時の表示秒数」（デフォルト10秒）のタイマーを起動。
    - 表示終了（タイマータイムアウト）時に、アバターの待機状態遷移、空文字のブロードキャストによるOBS側吹き出しの自動消去（HTML側の `hideBubble` 連動）、および次のキュー要求の実行を順番に処理。
7. **設定画面UIレイアウトの整理 (`src/ui/avatar_window.cpp`)**:
   - 設定タブ内の全ウィジェットを、機能毎に4つの `QGroupBox`（OBS/描画設定、Twitch連携設定、AI設定、外部通知設定）にグループ化して視覚的境界をわかりやすく整理。
   - 表示秒数（「次の要求がある時」「次の要求が無い時」）を `QHBoxLayout` を用いて横並びに配置し、コンパクトにまとめた。
    - WebHook URLの入力欄の最大幅を使いやすさを考慮して `400` へ適度に拡張。
    - 「OBS / 描画設定」グループ内に、OBSブラウザソースでローカルファイルとして直接読み込ませる `pic/avatar_obs.html` の絶対パスを表示する入力欄と、ワンクリックでクリップボードにコピーできる「パスをコピー」ボタンを追加。
    - ウィンドウの縦幅制限によって各入力ウィジェットが潰れて線状に変形するのを防ぐため、設定タブ全体を `QScrollArea` で包み、さらに生成する子ウィジェットの親（parent）をスクロールの中身である `scrollContent` へ正確に紐づけることで、レイアウト計算のバグを解消。
