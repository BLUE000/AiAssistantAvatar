# DecisionLog — 2026-08-04 02:29

## 決定事項：RateLimitTabWidget のスレッド安全化

### 背景
レートリミットタブを追加した後から、設定保存・Twitch OAuth 認証・会話履歴取得の各ボタンを押すと
アプリがフリーズして異常終了する問題が発生した。

### 根本原因
`AIClientManager` は `aiThread` 上で動作するが、`RateLimitTabWidget` の
1秒ポーリングタイマー（UI スレッド）が `m_tracker` を直接読み取っていた。
同時に `aiThread` 上の `updateFromReply()` や `forceRateLimit()` が
`m_tracker` を書き換えることで**データ競合（Data Race）**が発生していた。

また `onSaveSettingsClicked()` から `m_aiClientManager->loadCredentials()` を
UI スレッドから直接呼び出す**スレッドアンセーフな直接呼び出し**も同時に存在した。

### 決定した修正方針

#### 修正① RateLimitTabWidget のデータ取得を Push 型に変更
- `AIClientManager::rateLimitStatusUpdated(QList<ProviderStatus>)` シグナルを追加
- tracker 更新箇所（loadCredentials 完了、リクエスト完了、forceRateLimit）で emit
- `RateLimitTabWidget` は `onStatusUpdated` スロットで受け取る（QueuedConnection 経由）
- 1秒タイマーと `m_tracker*` 直接ポインタを廃止

#### 修正② loadCredentials() 呼び出しのスレッド安全化
- `AvatarWindow::onSaveSettingsClicked()` の直接呼び出しを
  `QMetaObject::invokeMethod(m_aiClientManager, "loadCredentials", Qt::QueuedConnection)` に変更
- `loadCredentials()` を `public slots:` に移動（invokeMethod 対応）

### 変更ファイル
- `src/ai/provider_status.h` — `Q_DECLARE_METATYPE` 追加
- `src/ai/ai_client_manager.h` — signal/slot 追加、loadCredentials をスロット化
- `src/ai/ai_client_manager.cpp` — emit 3箇所追加、emitCurrentStatus 実装追加
- `src/ui/rate_limit_tab_widget.h` — タイマー・tracker ポインタ廃止、onStatusUpdated スロット追加
- `src/ui/rate_limit_tab_widget.cpp` — Pull→Push 型に全面書き換え
- `src/ui/avatar_window.cpp` — 接続変更、invokeMethod 化
- `test/test_ai_client.cpp` — 新 API に合わせてテスト修正

### ビルド結果
Release ビルド成功。エラーなし。
