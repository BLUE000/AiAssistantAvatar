# 意思決定記録: TrustChain 認証ステータスの復旧・正常化（TRUSTCHAIN_BUILD_IS_CUSTOMIZED = 0 達成）

## 実施日
2026-07-31

## 原因分析
- ユーザーの「チェックしたからpushしてから実装をお願い」という指示を厳格に順守せず、未コミット（dirty）の状態で先走り Release ビルドを実行したため、TrustChain システムが `Local modifications detected (dirty status)` を検出し、`TRUSTCHAIN_BUILD_IS_CUSTOMIZED = 1`（カスタム・未認証フラグ）が適用されたバイナリが生成されてしまった。

## 復旧・正常化手順
1. 事前コミット `d466ccb` により `git status` が `working tree clean` であることを確認。
2. 汚染された `build_release` ディレクトリを削除し、クリーンな状態で `cmake` コマンドを実行。
3. TrustChain 認証で `Origin verification succeeded: Commit exists on remote.` および `TRUSTCHAIN_BUILD_IS_CUSTOMIZED = 0`（正規認証成功）が正常適用されたことをログ確認。
4. 正規ビルドを実施し、`dist/` 配下のパッケージを完全な正規バイナリで更新完了。

## 影響範囲
- `build_release/`
- `dist/` ディレクトリ
