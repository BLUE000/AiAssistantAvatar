# 意思決定記録: HuggingFaceおよびOpenRouterにおけるモデル全自動動的選択・エラー診断強化機能の導入

## 実施日
2026-07-29

## 背景・課題
HuggingFace および OpenRouter などの外部 LLM API プロバイダでは、提供されるモデルの追加・廃止、アクセス制限 (Gated models)、無料枠ラインナップの変更が日々発生します。
従来の固定モデル名（例: `meta-llama/Llama-3.1-8B-Instruct`）によるリクエスト送信では、アクセス権限不足やモデル非サポートにより HTTP 400 (Bad Request) や HTTP 404 (Not Found) が発生し、「不正なリクエスト形式」などの抽象的なエラー表示で対話が停止する問題がありました。

## 意思決定内容
1. **`/v1/models` エンドポイントによる全自動モデル取得・最適選出の導入**:
   - `HuggingFaceAIClient` および `OpenRouterAIClient` において、リクエスト送信時または初期化時に `/v1/models` エンドポイントを呼び出し、ユーザーのアカウント/APIキーで現在即座に利用可能な最良モデル（HuggingFace では対話用 Instruct モデル、OpenRouter では利用可能な `:free` 無料枠モデルまたは最適モデル）を全自動抽出して動的に適用します。
   - ユーザーにモデル名を意識・手動入力させない全自動化を実現します。
2. **リクエスト構造の標準化とエラー詳細パースの強化**:
   - `max_tokens: 1024` や `stream: false` をリクエスト JSON に明示的に付与し、API 側のバリデーションエラーを予防します。
   - HTTP 400/404/403 等のレスポンス JSON (`detail`, `error`, `message` キー) から具体的なエラー理由を抽出し、ログおよび画面表示で可視化します。
