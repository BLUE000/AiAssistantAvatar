# 意思決定記録: HuggingFace / さくらAI への Tavily Web検索(tools / tool_calls)の完全実装と全クライアント横展開

## 実施日
2026-07-30

## 背景・課題
1. 前回 OpenRouterAIClient に Tavily Web 検索機能 (`tools` 付与および `tool_calls` 解析) を追加した際、`HuggingFaceAIClient` および `SakuraAIClient` への同等機能の移植が不足しており、HuggingFace 選択時に Tavily Web 検索が発火せず天気情報を取得できない状態となっていた。

## 意思決定内容
1. **HuggingFaceAIClient の Web 検索機能完全追加**:
   - `sendRequest` 時に `tools` (web_search) を付与。
   - `on_networkReplyFinished` にて `tool_calls` を判定し、`m_searchManager->executeSearch()` を呼び出す。
   - `on_searchFinished` で検索結果をアタッチして二次レスポンスを取得する。
2. **SakuraAIClient の Web 検索機能完全追加**:
   - `sendRequest`, `on_networkReplyFinished`, `on_searchFinished` に同様の Tavily Web 検索連動処理を追加。
3. **全クライアント総点検**:
   - Groq, Mistral, Cerebras, OpenRouter, HuggingFace, Sakura の全 6 クライアントで Web 検索機能が均質に動くことを確認。

## 影響範囲
- `src/ai/huggingface_ai_client.h` / `cpp`
- `src/ai/sakura_ai_client.h` / `cpp`
