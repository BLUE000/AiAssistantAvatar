# 意思決定記録: さくらAIにおける事前検索型RAG (方法B) 導入によるWeb検索連携と Bad Request (400) エラー回避

## 実施日
2026-07-30

## 背景・課題
- さくらAI サーバー（`llm-jp-3.1-8x13b-instruct4`）は vLLM の構成上 Native な `tools` (Function Calling) パラメータを拒否して HTTP 400 エラーを返す。

## 意思決定内容
1. **`tools` パラメータの除外**:
   - `SakuraAIClient` から送信するリクエスト JSON から `tools` パラメータを除外し、さくらAI の HTTP 400 エラーを完全解決する。
2. **事前判定型 Web 検索 (RAG 方式) の導入**:
   - リアルタイム情報や天気・最新ニュース等に関するクエリの場合、さくらAI へ送る前にアプリ側で Tavily Web 検索を先行実行し、得られた検索結果をコンテキストとしてシステムプロンプトに注入してからさくらAI へ送信する。
   - これにより、通信エラーを回避しつつ高速かつ正確な最新天気・リアルタイム情報応答を実現する。
